# 浪花亭ごん太の世界ボヤき帳 — 連載仕様

毎朝 6:00 JST に、前日の世界の時事ネタを題材にした読了5分のエッセイを生成し、
note に貼り付けられる形で「入稿ページ」に掲載する連載の仕様書。

## 概要

| 項目 | 内容 |
| --- | --- |
| 配信時刻 | 毎日 6:00 JST（cron `0 21 * * *` UTC） |
| 生成物 | note 入稿ページ（Artifact）の更新 1点 |
| 入稿ページ | https://claude.ai/artifact/Rx7JosMgBtCnV9ZLe6Vw5e |
| 題材 | 前日（JST）の世界の時事ネタ 4〜5本 ＋ 締めの明るいネタ 1本 |
| 分量 | 日本語 2,400〜3,000字（読了5〜6分） |
| 語り手 | 浪花亭ごん太（本連載のための架空の関西芸人キャラクター） |
| 実際の投稿 | note への公開は手動（note に投稿APIがないため） |

記事本文はこのリポジトリには保存しない。入稿ページが最新号と直近14号を保持する。

## 設計上の決定事項

### 1. 実在の芸人名は使わない

「大物関西芸人の視点」という企画意図は、**オリジナルの架空キャラクター**で実現する。
実在の芸能人の名前を冠して架空のコメントを書くと、本人が発していない意見を本人の発言として
流通させることになるため。記事末尾には毎回その旨のお断りを入れる。

### 2. 事実とボヤきを分ける

各ネタは「【事実】…（出典名）」→「ボヤきの地の文」の順で構成する。
読者が「どこまでが報道で、どこからが語り手の意見か」を判別できるようにするため。
主観には文末に「知らんけど」を付け、意見であることの印として機能させる。

### 3. 死者・負傷者が出た話は茶化さない

そのネタではボケを一度やめ、静かな敬意をもって短く書く。連載の信用はここで決まる。

### 4. JST で日付を確定する

旧ルーティン（`朝のまとめ`）は、セッションの UTC 日付をそのまま使っていたため、
JST 6:00 の実行が前日付になり、本文も前日の天気を「今日」として配信していた。
本連載のプロンプトでは冒頭で `TZ=Asia/Tokyo date` を実行し、JST の日付を使うことを必須にしている。

### 5. 毎日ちがう切り口にする

執筆前に入稿ページの ISSUE と ARCHIVE を読み、直近の切り口と同じ型を連続で使わない。
テンプレートをなぞるだけの記事にしないための仕組み。

### 6. note は Markdown を解釈しない

note の編集画面に Markdown を貼ると記号がそのまま残る。よって本文はプレーンテキストで書く。
`**` `##` `[](URL)` を使わず、見出しは「■ 」、事実ブロックは「【事実】」で表す。
出典は「媒体名：URL」を1行ずつ。URL だけの行にすると note が重い埋め込みカードにしてしまう。

### 7. 最後の1本は、明るいネタで締める

本編のあと、オチの直前に「読んだ人がホッとして、明るくなるネタ」を必ず1本置く。
世界情勢を扱う以上、放っておくと紛争・物価・政治の暗い話だけで朝が終わる。
それは読者にとっても連載にとっても持続しない。

この枠では皮肉やオチで落とさず、素直に「ええ話や」として書く。
語り手自身がホッとした、という書き方で読者と並ぶ。
オチは、この明るいネタに一度触れてから締める。

避けるのは「悲劇の中の美談」。死者が出た事故の救出秘話などは、
その日の暗いネタの傷をなぞることになるので、締めには使わない。

第2号（2026-09-23）の例：カリフォルニアの温泉で見つかった新種のアメーバ
Incendiamoeba cascadensis が、複雑な生き物の耐熱記録を6度引き上げた話。
「崖っぷち」という当日の切り口を、限界の向こう側で普通に暮らす生き物の話で受けた。

### 8. 語り口は「短気で直球、でも後を引かん」

第1〜3号の初稿は、上方の芸人というより穏やかなエッセイストになっていた。
関西弁ではあるが、一度も跳ねない。事実を受けていきなり分析に入る。一段落が長い。
これでは連載の芸風が立たないため、語り口の仕様を書き直した。

書き方の型：
- 事実ブロックの直後は、まず短いツッコミ一発から入る。説明はその後
- 引っかかった数字や固有名詞を、そのまま突き返す（「479人。」「三日でっせ。」）
- 文を短く切る。1段落は1〜3文
- カッとなって、すぐ戻る。怒鳴った次の段落ではもう笑っている
- 1記事に1つ、語り手自身の楽屋話や失敗談を混ぜる。偉そうにならないための装置
- 最後に自分をいじる一言で終わる

強さの調節：
- 強いツッコミは1記事3〜4発まで。同じ言い回しを2回使わない
- 死者・負傷者が出た話では声を張らない。一度静めてから、短く、静かに書く
- 締めの明るいネタでは怒らない。素直に受ける
- 怒る相手は権力者の振る舞いと建前だけ。被害者や一般の人には向けない
- 事実ブロックだけはきっちりした書き言葉で正確に。ここでふざけない。落差が芸になる

実在の落語家・芸人の名前は、語り手としても比較としても一切出さない。
芸風の質感だけを仕様に落とし込み、名前は使わない。

## 経緯：投稿先の変遷

1. **Notion（2026-09-22 開始、09-23 で終了）** — データベース「ボヤき帳アーカイブ」に毎朝1ページ。
   第1号・第2号がここに残っている。Notion は保管庫としては優秀だが、フィードもフォローもないため
   読者が来ない。ユーザーの希望（読まれること）に合わないので終了した。
2. **note（現行）** — 読者の回遊がある。ただし外部から投稿する API がないため、
   生成は自動・投稿は手動（コピペ）の半自動運用とする。

## 既知の制約

- `create_trigger` API は、この組織では `connectors` パラメータを受け付けない。
  そのため API 経由で作った Routine には Notion 等のコネクタが紐づかない。
  現行の note 運用はコネクタを必要としない（Web検索と Artifact のみ）ので影響しない。
- note には投稿 API がないため、公開操作は手動。
