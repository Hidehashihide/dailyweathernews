## 1. 検出し修正した不具合（11件）

### 🔴 #1 セーブ/ロードで乱数状態が破壊される
| | |
|---|---|
| 重大度 | **Critical（進行状況の破壊）** |
| 発見 | `tests/rng.test.ts` プロパティテスト |
| 症状 | `Rng.save()` が負の値を返すことがあり、ロード時に `safeInt` が0へクランプ。乱数列が別物になる。4語すべてが0になれば完全に再初期化される |
| 原因 | sfc32 の更新式で `^` と `<<` が**符号付き**32bit整数を返すため、状態が負になる。メモリ上はコンストラクタが `>>> 0` で正規化するため往復して見えるが、JSON経由では検出されない |
| 修正 | `save()` で4語すべてを `>>> 0` して返す。内部状態も更新時点で符号なしに正規化 |
| 回帰テスト | `rng.test.ts`「saved state is always four uint32 words」、`save.test.ts`「keeps rng words unsigned through JSON」 |

> セーブデータ破損系はユーザーからの再現報告が最も困難な種類の不具合。メモリ内往復テストだけでは検出できず、「保存した値の範囲」を検査して初めて見つかった。

### 🔴 #4 ZWJ絵文字が分解され、文字数が3倍になる
| | |
|---|---|
| 重大度 | **High（正当な入力の破壊）** |
| 症状 | 家族絵文字（👨‍👩‍👧）を含むキャプションが「長すぎます」で拒否される。1文字のはずが3文字として数えられる |

| 回帰テスト | `text.test.ts`（家族絵文字=1文字、旗=1文字、結合文字=1文字）、`moderation.test.ts`「measures length in graphemes」 |

## 2. 確認済みで問題がなかった項目

| 項目 | 結果 |
|---|---|
| **XSS / HTMLインジェクション** | プレイヤーが書いたキャプションは `textContent` のみで描画。実ブラウザで `<img src=x onerror=...>` を投入し、要素生成なし・スクリプト実行なし・文字列として表示されることを確認 |
| **不正セーブによる能力改変** | 展示品のスコアはロード時に必ず再計算。改造セーブで `tipMultiplier: 9999` を仕込んでも上限3.0に収まる |
| **セーブのパストラバーサル** | Electron側でセーブキーを `^[A-Za-z0-9._-]{1,64}$` に制限。`../` は拒否 |
| **クラッシュ耐性** | 任意文字列・任意JSON・孤立サロゲートを各800〜1,500ケース投入し、`loadGame` / `moderateCaption` / `scoreCaption` のいずれも例外を送出しない |
| **金銭の不変条件** | NaN・Infinity・負値を混ぜた40回連続演算でも、常に安全な整数かつ0以上 |
| **購入の原子性** | 残高不足の購入は残高・所持品ともに一切変更しない |
| **ケース購入の価格整合** | 段階的にアップグレードした場合と一気に最上位を買った場合のコストが一致 |
| **決定論** | 同一シード＋同一操作列で完全に同一の状態。80日分で検証 |
| **セーブサイズ** | 1,500日プレイ後で約53KB。ログ・レポートの上限が効き、日数に対して線形に増えない |
| **レスポンシブ** | 360px / 1280px のいずれでも横スクロールなし。全ボタンが44px以上 |
| **ライトテーマ** | `prefers-color-scheme: light` で背景が明示的に塗られる |
| **1日あたりの処理時間** | 平均25ms未満（上限600人の来館者を個別シミュレーションした場合） |

## 3. 未修正：バランス上の問題（要判断）

実装上の不具合ではなく**ゲーム設計の判断**が必要なため、修正せず報告する。

### ⚠️ B-1 展示枠が30日台で上限に達する

ランダム行動のボットで計測（3シード）:

| シード | 展示枠12（上限）到達日 |
|---|---|
| b1 | 37日目 |
| b2 | 33日目 |
| b3 | 32日目 |

**問題**: 「所有と略奪」が本作の中核だが、拡張要素が1ヶ月で尽きる。以降は新規性が投票と略奪だけになる。

**原因**: `slotPrice` が `150 × 1.85^n` で、追加9枠の総額が約44,600。一方で収入は指数的に伸びるため、価格上昇が追いつかない。

**推奨**: 次のいずれか。
1. 上限を12→24に引き上げ、係数を1.85→2.3へ
2. 枠だけでなく「棟（テーマ別展示室）」を第2の拡張軸として追加する
3. 枠の価格を金銭ではなく**権威**で支払わせる（権威は伸びが緩やかなため自然な律速になる）

### ⚠️ B-2 所持金が500日台で上限に張り付く

| シード | 9,999,999 到達日 |
|---|---|
| b1 | 504日目 |
| b2 | 524日目 |
| b3 | 517日目 |

参考推移（b1）: 10日 ¥4,274 → 60日 ¥95,564 → 200日 ¥1,777,990 → 400日 ¥6,576,000

**問題**: 上限に達すると経済が意味を失う。クランプにより破綻はしないが、遊びが止まる。

**推奨**: 恒久的な資金シンク（維持費、修復費、保険料）の導入、または収入の逓減曲線の導入。長期運営を前提とするなら前者が望ましい。

> なお、人間のプレイで500日到達は現実的ではない（1日1〜2分として8〜16時間）。優先度はB-1の方が高い。

|---|---|

## 5. 再現手順

```bash
cd apps/my-fake-museum
npm install

npm run typecheck          # 型検査
npm test                   # ユニット + プロパティ + シミュレーション（225件）
npm run test:cov           # カバレッジ付き
npm run test:e2e           # 実ブラウザE2E（ビルド込み）

DAYS=1500 SEEDS=4 npm run sim   # 長時間ソーク（約36秒）
DAYS=10000 SEEDS=8 npm run sim  # リリース前の本番ソーク
```

不変条件の定義は [`tests/invariants.ts`](./tests/invariants.ts) に集約してある。新しい不変条件はここに追加すれば、ユニットテストとソークの両方に自動的に反映される。
