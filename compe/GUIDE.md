# コンペ参加ガイド：「寝る前5分」ジャーナリングアプリ

対象お題：忙しい社会人（36歳・田中さん）向け「寝る前5分」ジャーナリングアプリを、
生成AI（LLM API）を活用して**単一HTML**で実装する。
作業時間目安：3〜5時間。審査は運営提供のサンプル日記を読み込ませた出力で行われる。

---

## 0. まず押さえる「勝ち筋」

お題文に答えが書いてあります。

> 差がつくのはAIの性能ではありません。全員が同じサンプル日記を処理するからこそ、
> **"良いまとめに必要な情報をどう構造化してAIに渡すか"** というプロンプト設計と、
> 続けたくなる体験の設計が、そのまま出力の差になります。

つまり勝負どころは2点だけです。

| 勝負どころ | 具体的に何をするか |
| --- | --- |
| A. 入力の構造化 | 自由記述をそのままAPIに投げず、**問い・タグ・数値・過去履歴を構造化したJSON**として渡す |
| B. 出力の構造化 | 「文章を返す」のではなく**JSONスキーマを指定**して受け取り、UIで意味のある形に描画する |

負けパターンは「日記テキストを丸ごと投げて要約させ、そのまま `<div>` に流し込む」アプリ。
これは審査員が何十個も見るものなので、絶対に避けます。

### 評価5基準と、それに答える打ち手

| 基準 | 審査で見られること | 本ガイドでの打ち手 |
| --- | --- | --- |
| ①AIへのプロンプト設計力 | まとめ生成のプロンプトに意図と工夫があるか。**日付・その日の入力・振り返りの観点**など、良いまとめに必要な情報を**セットで**AIに渡せているか | §3 の入力JSON（date/weekday を明示的に含める）＋ §4 のプロンプト骨子 |
| ②AIの出力品質（パーソナライズ） | 一般論に終わらず、田中さんが"自分ごと"として読めるか。**サンプルの内容に即している**か | §4 の引用強制・創作禁止・定型労い禁止の制約 |
| ③気づき・振り返りの深さ | 単なる要約に留まらず、**複数日**から傾向・変化・気づきを引き出せているか | §1-③ の週次振り返り＋ローリングサマリー、根拠（日付・引用）必須 |
| ④UI・操作性 | 寝る前5分、疲れていても迷わず使えるか。入力→まとめ表示が直感的か | §5 の体験設計 |
| ⑤独自性 | 一般的な記録アプリや単純なAI要約では得られない仕組み・体験。**問いの設計／まとめ方／気づきの見せ方**のどこに独自性があるか | 下記「⑤独自性の作り方」 |

①の「日付・その日の入力・振り返りの観点を**セットで**渡す」は、採点者が中身を見る前提の文言です。
プロンプトを組み立てている箇所をコード内でコメント付きの1関数にまとめ、
渡している要素が一目で分かるようにしておいてください（動画でもそこを映す）。

### ⑤独自性の作り方

基準⑤は「問いの設計・まとめ方・気づきの見せ方」の**3箇所を名指し**しています。
全部に手を広げず、**1箇所を尖らせて言い切る**のが得策です。候補：

- **問いの設計で差をつける（推奨）**：3問目を固定にせず、**直近の記録からAIが今日だけの問いを1つ生成**する。
  「昨日『レビューで詰まった』と書いていたけど、あれはどうなった？」のように前日を引用して聞く。
  → ガイド付きの問い（①）でありながら、パーソナライズ（②）と変化の可視化（③）も同時に満たすため、
    1つの仕掛けで基準4つに効きます。**単純なAI要約アプリでは絶対に出せない体験**なので独自性の説明もしやすい。
- **まとめ方で差をつける**：「あなたの言葉」と「AIの解釈」を左右に対比表示し、引用が根拠であることを視覚化する。
- **気づきの見せ方で差をつける**：週次で「先週のあなた → 今週のあなた」を1行ずつ並べたbefore/after表示。

提出物・動画では「このアプリの独自性は◯◯です」と**一文で言い切れる状態**にしておくこと。
審査員が独自性を探さないと見つからないアプリは、⑤で点が入りません。

## 1. 3つの課題 → 3つの機能の対応表

お題が明示している3つの構造的課題に、機能を1:1で対応させます。
**この対応関係を README と動画で明示することが、そのまま評価点になります。**

### ① 「続かない」→ ガイド付きの問い

- 白紙のテキストエリアを出さない。**3問固定 + 選択式**にする。
- 例：
  1. 気分タグ（選択式・複数可）：`疲れた / 充実 / モヤモヤ / 焦り / 淡々 / 達成感`
  2. エネルギー（1〜5のスライダーまたはボタン）
  3. 「今日いちばん頭に残っていることは？」（1行・任意）
  4. 「小さくても前に進んだことは？」（1行・任意）
- **全部スキップ可能**にする。タグを1つ押すだけでも成立する設計にすると「続く」。
- 所要30秒で終わることを画面上で示す（プログレス、「あと2問」表示など）。
- 田中さんは筋トレ習慣がある人物設定なので、「習慣」「積み重ね」の文脈をタグや問いに入れると刺さります。

### ② 「整理されない」→ 今日の自分に刺さるAIのまとめ

一般論を返させないための**プロンプト上の制約**が肝です。

- ユーザーが書いた語をそのまま**引用してから**解釈させる（引用必須制約）。
- 禁止事項をプロンプトに明記：「一般的な助言をしない」「『お疲れ様です』などの定型挨拶を書かない」
  「ユーザーが書いていない出来事を創作しない」。
- 出力は必ず**今日の入力に固有の語**を含むこと、を条件にする。

### ③ 「変化が見えない」→ 複数日からの傾向・気づき

- 記録は `localStorage` に日付キーで蓄積。
- **サンプル日記（複数日分）を一括投入できる導線を必ず作る**（後述、審査で最重要）。
- 「週の振り返り」ボタンで、蓄積された複数日の構造化データをまとめてAPIに渡し、
  傾向・変化・気づきを出力させる。
- グラフ（気分/エネルギーの推移）を軽くでも描くと「変化が見える」が視覚的に伝わります。

## 2. 審査で落とさないための必須導線 ★最重要

> 審査は、運営が用意するサンプル日記（別紙参照）を読み込ませたときの出力で行います。

**審査員がサンプル日記を投入できないアプリは、それだけで評価不能になります。**
以下を必ず実装してください。

1. 画面上に「サンプル日記を読み込む」ボタン、または**テキスト貼り付け→取り込み**の入力欄を置く。
2. 貼り付けられた複数日分のプレーンテキストを、**LLMに一度パースさせて**日付ごとの構造化データに変換し、
   自アプリのデータ形式に流し込む（正規表現でのパースは形式差で壊れるので非推奨）。
3. 取り込み後、そのまま「日次まとめ」「週次の振り返り」の両方が動くこと。
4. APIキー入力欄を画面に用意する（`localStorage` に保存、`type="password"`）。
   審査員が自分のキーを入れて動かせる状態にしておく。キーをコードに直書きして提出しない。

この導線の有無で、上位/圏外がはっきり分かれます。最初に作ってください。

## 3. 技術設計（単一HTML）

```
index.html   ← これ1枚だけ。CSS/JSは <style> / <script> にインライン
```

- 依存ライブラリはゼロか、CDN 1本まで。単一HTMLの縛りを守る。
- 状態：`localStorage` に `entries: { "2026-09-03": {...} }` を保存。
- API呼び出しは `fetch` で直接。**JSONモード/スキーマ指定**を使い、パースの失敗を防ぐ。
- 失敗時のフォールバック（キー未入力・通信エラー・JSON不正）を必ず用意する。動画収録中に落ちると致命傷。

### LLMに渡すデータ構造（例）

```json
{
  "today": {
    "date": "2026-09-03",
    "weekday": "水",
    "mood_tags": ["疲れた", "達成感"],
    "energy": 2,
    "highlight": "レビューで詰まった仕様がやっと通った",
    "small_win": "23時前に切り上げてジムに寄れた"
  },
  "recent": [
    { "date": "2026-09-02", "mood_tags": ["焦り"], "energy": 2, "summary_line": "..." },
    { "date": "2026-09-01", "mood_tags": ["淡々"], "energy": 3, "summary_line": "..." }
  ]
}
```

ポイント：過去分は**全文ではなく1行サマリー＋数値**だけを渡す（ローリングサマリー方式）。
トークンを抑えつつ「変化」を語れる情報だけを持たせる、という設計判断そのものが評価対象です。

### LLMから受け取る出力スキーマ（例）

```json
{
  "mirror": "あなたは『やっと通った』と書いた。",
  "insight": "詰まりを抜けた日にエネルギーが上がる傾向が3日連続で出ている。",
  "gained": ["粘って通した仕様", "23時前の切り上げ"],
  "pattern": "先週より就寝前の余白が15分増えている",
  "tomorrow_action": "明日は最初の30分をレビュー返信に固定する",
  "mood_score": 3
}
```

フィールドごとにUIの見せ方を変える（引用は大きく、行動は1枚のカードに）ことで、
「ただの要約表示」との差が一目でつきます。

## 4. プロンプト設計の骨子（そのまま叩き台に使えます）

### 日次まとめ用

```
あなたは、夜の振り返りに寄り添う記録の相棒です。相手は仕事に追われて疲れきった36歳の会社員です。

【入力】以下のJSONが今日の記録と直近数日の記録です。
{data}

【必ず守ること】
1. 出力の冒頭は、ユーザーが今日実際に書いた語句をそのまま一箇所引用することから始める。
2. ユーザーが書いていない出来事・感情を創作しない。書かれていないことは推測せず、書かれた範囲で述べる。
3. 一般的な助言（「休息も大切です」等）、定型の労い（「お疲れ様でした」等）を書かない。
4. 直近の記録と比べて変化があれば1点だけ指摘する。変化が読み取れない場合は無理に書かず pattern を空にする。
5. 明日の行動は「5分以内で終わること」を1つだけ、具体的な動詞で書く。
6. 全体で200文字以内。深夜に読むため、短く、断定しすぎず、評価や採点をしない。

【出力】次のJSONのみを返す。前後に説明文をつけない。
{ "mirror": string, "insight": string, "gained": string[], "pattern": string, "tomorrow_action": string, "mood_score": 1-5 }
```

### 週次の振り返り用

```
以下は同一人物の複数日の記録です。
{entries}

日ごとの感想ではなく、【日をまたいで初めて見えること】だけを書いてください。
- 繰り返し現れている語や状況（頻度を数えて示す）
- エネルギーや気分の推移と、それに連動している出来事
- 本人が気づいていなさそうな因果や偏り
- 1日単位では見えず、複数日を並べたからこそ言えること

一般論・励まし・アドバイスの羅列は禁止。各項目に必ず日付または引用を根拠として添える。
出力JSON: { "recurring": [{"theme": string, "count": number, "evidence": string[]}],
            "trend": string, "blind_spot": string, "one_change": string }
```

**「引用を根拠として添えさせる」制約が、一般論を潰す最も効く手です。**

## 5. 「寝る前5分」の体験設計（UI）

- ダークテーマを既定に。深夜の画面まぶしさ対策であることを動画で言及する。
- 文字は大きく、タップ領域は広く。片手・寝転がった状態を想定。
- 起動 → 3秒で入力開始できること。ログイン・設定画面を挟まない。
- 入力完了 → AIまとめ表示までのローディングに「今日の記録を読み返しています」など待ち時間の演出。
- 最後に「おやすみなさい」で閉じる。次の行動を要求して終わらない。
- 連続記録日数の表示（筋トレ習慣がある人物設定と相性が良い）。ただし途切れを責めない文言にする。
