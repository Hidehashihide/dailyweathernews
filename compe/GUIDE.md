# コンペ参加ガイド：「寝る前5分」ジャーナリングアプリ

お題：忙しい社会人（36歳・田中さん）向け「寝る前5分」ジャーナリングアプリを、
生成AI（LLM API）を活用して**単一HTML**で実装する。作業時間目安：3〜5時間。
審査は運営提供のサンプル日記（→ [`sample-diary.md`](./sample-diary.md)）を読み込ませた出力で行う。

このガイドは、お題文＋別紙（制作要件・提出物・評価基準・サンプル日記）を反映済み。

---

## 0. まず押さえる「勝ち筋」

お題文が答えを明言しています。

> 差がつくのはAIの性能ではありません。全員が同じサンプル日記を処理するからこそ、
> **"良いまとめに必要な情報をどう構造化してAIに渡すか"** というプロンプト設計と、
> 続けたくなる体験の設計が、そのまま出力の差になります。

勝負どころは2点だけ。

| 勝負どころ | 具体的に何をするか |
| --- | --- |
| A. 入力の構造化 | 自由記述をそのままAPIに投げず、**日付・曜日・その日の入力・振り返りの観点・過去履歴を構造化したJSON**として渡す |
| B. 出力の構造化 | 「文章」で受け取らず**JSONスキーマを指定**して受け、フィールドごとにUIの見せ方を変える |

負けパターンは「日記テキストを丸ごと投げて要約させ、そのまま `<div>` に流し込む」アプリ。
審査員が何十個も並べて見るので、これは埋没ラインです。

### 評価5基準と、それに答える打ち手

| 基準 | 審査で見られること | 打ち手 |
| --- | --- | --- |
| ①プロンプト設計力 | **日付・その日の入力・振り返りの観点**など必要な情報を**セットで**渡せているか | §5 の入力JSON＋§6 のプロンプト |
| ②出力品質（パーソナライズ） | 一般論に終わらず**サンプルの内容に即した**"自分ごと"になっているか | §6 の引用強制・創作禁止・定型労い禁止 |
| ③気づき・振り返りの深さ | 単なる要約でなく**複数日**から傾向・変化・気づきを引き出せているか | §3 の狙う出力水準＋§6 週次プロンプト |
| ④UI・操作性 | 寝る前5分、疲れていても迷わず使えるか | §7 の体験設計 |
| ⑤独自性 | **問いの設計／まとめ方／気づきの見せ方**のどこに独自性があるか | §2 の独自性フック |

①は「プロンプトの中身を読む」前提の文言で、実際**提出物③としてプロンプト全文を出す**ことになります。
プロンプトを組み立てる箇所を**コメント付きの1関数**にまとめ、渡している要素が一目で分かる状態にしてください。

## 1. 必須要件チェック（別紙より・落とすと失格級）

| # | 要件 | 実装メモ |
| --- | --- | --- |
| 1 | **単一HTMLファイルで完結**（ブラウザで開けば動作） | CSS/JSは `<style>`/`<script>` にインライン。外部ファイル依存なし |
| 2 | その日の感情・出来事を記録できる入力（**ガイド付きの問い推奨**） | 白紙のテキストエリアを最初に出さない |
| 3 | **実行時にLLM APIを呼び出し**、パーソナライズされたまとめ・気づきを生成 | 事前生成やハードコードは不可 |
| 4 | **運営提供のサンプル日記を読み込ませて出力を生成できること** | §4。ここが無いと審査不能 |
| 5 | 寝る前5分・疲れていても迷わない直感的操作 | §7 |
| 6 | **提出コードからAPIキーを削除、またはプレースホルダに** | 画面のキー入力欄＋`localStorage`。コード直書き禁止 |
| 7 | **安全設計**（下記） | ★見落としやすい。必ず実装 |

### 要件7「安全設計」の中身（原文）

> 日常の内省・記録の範囲に限定すること。AIのまとめは**決めつけ・心理診断ではなく**、
> **本人の言葉を映して整理する**ものにする。**メンタルヘルスの助言・診断は行わず**、
> **深刻な内容が入力された場合には公的な相談窓口を案内する導線**を入れること。

実装は3層で。

1. **プロンプトの制約**：「診断・断定・ラベリングをしない」「メンタルヘルスの助言をしない」
   「本人の言葉を引用して映すことに徹する」を明記。
2. **出力スキーマにフラグ**：`needs_support: boolean` を持たせ、深刻な内容を検知したら
   まとめの代わりに/まとめと並べて**相談窓口カード**を表示する。
3. **常設の導線**：フラグ検知に頼りきらず、画面下部に小さく「気持ちがつらいときは」リンクを常設。

案内先（公的窓口）の例：
- 厚生労働省「まもろうよ こころ」 https://www.mhlw.go.jp/mamorouyokokoro/
- こころの健康相談統一ダイヤル 0570-064-556
- よりそいホットライン 0120-279-338

**この安全設計は「本人の言葉を映して整理する」という要件2と表裏一体**で、
そのまま §6 の「引用を強制する」プロンプト設計と同じ方向を向いています。
つまり安全要件を守るほど、②パーソナライズの評価も上がる構造になっています。ここは素直に守るのが得。

## 2. 3つの課題 → 3つの機能 ＋ 独自性フック

### ① 「続かない」→ ガイド付きの問い

- 白紙を出さない。**タグ選択 + 1〜5スケール + 短い問い2〜3個**。
- 例：気分タグ（疲れた/充実/モヤモヤ/焦り/淡々/達成感）、エネルギー1〜5、
  「今日いちばん頭に残っていることは？」「小さくても前に進んだことは？」
- **全部スキップ可**。タグ1つ押すだけでも成立させる。所要30秒であることを画面で示す。
- 田中さんは筋トレを習慣にしている人物設定なので、「積み重ね」の文脈をタグや文言に入れると刺さる。

### ② 「整理されない」→ 今日の自分に刺さるまとめ

一般論を返させないための**プロンプト上の制約**が肝（§6）。

### ③ 「変化が見えない」→ 複数日からの傾向・気づき

- `localStorage` に日付キーで蓄積。過去分は**1行サマリー＋数値**に圧縮して渡す（ローリングサマリー）。
- 「週の振り返り」で複数日をまとめてAPIに渡す。気分/エネルギーの推移グラフを軽くでも描くと、
  「変化が見える」が視覚的に伝わる。

### ⑤独自性フック（1箇所を尖らせて言い切る）

基準⑤は「問いの設計・まとめ方・気づきの見せ方」の**3箇所を名指し**しています。
全部に手を広げず1つに絞るのが得策。推奨は **問いの設計**：

> **3問目を固定にせず、直近の記録からAIが「今日だけの問い」を1つ生成する。**
> 例：「昨日『休みを無駄にしてないか』と書いていたけど、今日はどうだった？」

理由：この仕掛け1つで基準①②③④に同時に効きます。
ガイド付きの問い（①）でありながら、前日を引用するのでパーソナライズ（②）、
日をまたぐので変化の可視化（③）、しかも入力の手が止まらない（④）。
そして「単純なAI要約アプリでは絶対に出せない」ので、⑤の説明が一文で済みます。

他の候補：
- **まとめ方**：「あなたの言葉」と「AIの解釈」を左右に対比表示し、引用が根拠であることを視覚化。
- **気づきの見せ方**：週次で「先週のあなた → 今週のあなた」のbefore/after 1行対比。

提出物④のメモと動画で「このアプリの独自性は◯◯です」と**一文で言い切れる状態**にしておくこと。
審査員が探さないと見つからない独自性は、⑤で点が入りません。

## 3. サンプル日記の読み解き ★ここが③と⑤の分かれ目

サンプルは**6/2（月）〜6/8（日）の7日分**、1日1段落の自由記述です（→ [`sample-diary.md`](./sample-diary.md)）。
全員が同じ入力を使う以上、**「この7日から何を言えるか」の差がそのまま順位**になります。

### 誰でも出せる（＝差がつかない）出力

- ジムに行った日は調子が良い（6/4・6/7・6/8 — **本人が6/8で自分で書いている**）
- 人と関わった時間が嬉しかった（6/5・6/6 — **これも本人が6/8で書いている**）

本人がすでに書いていることをなぞるだけの出力は、**要約に留まっている**と判定されます（基準③）。

### 本人がまだ気づいていない＝狙うべき水準

- **6/3の問いに、6/5が答えている。**
  6/3「これって成長してるのか、ただ回してるだけなのか分からない」
  → 6/5「自分の経験がそのまま役に立って、ありがとうございますと言われた」。
  経験が他人に渡せる形になっていることが成長の証拠なのに、本人は2つを結びつけていない。
  **日をまたがないと絶対に出ない気づき**で、基準③に直撃します。
- **満足の源泉が、一週間すべて仕事の外側にある。**
  嬉しかった/満たされたと書いた瞬間は、ジム・後輩・同期の3つ。
  自分の業務成果から満足を得た日が7日間で一度もない、という**不在**には本人も触れていない。
- **焦りが平日と休日を貫通している。**
  6/2「何をしたか思い出せない」・6/3「ただ回してるだけ」・6/7「休みを無駄にしてないか」。
  テーマは「時間の使い方への不全感」で、休んでも消えていない。
- **記録の粒度そのものが変化している。**
  6/2「何をしたのかうまく思い出せない」→ 6/8 具体的に振り返れている。
  書くことで想起できる量が増えている＝このアプリの価値そのもの。

> ⚠️ **これらを出力にハードコードしないこと。** 審査でバレますし、そもそも要件3（実行時にLLMを呼ぶ）違反です。
> やるべきは、**この水準の気づきがAIから自然に出てくるようにプロンプトを設計すること**。
> 具体的には「本人が書いていない結びつきを探せ」「感情が動いた瞬間の共通項を挙げよ」
> 「1日単位では見えず複数日を並べたからこそ言えることに限れ」と指示し、
> **各指摘に日付と引用の根拠を必ず添えさせる**（§6）。上の気づきは、この指示から実際に出てきます。

### 取り込み設計への示唆

- 日付表記は `6/2（月）` 形式で**曜日つき**。年は無い。
- 1日1段落・改行区切り。全体で1000字強。
- 別紙は「問い形式であれば内容を対応する項目に反映」と明記 → **自由記述を、アプリの問い項目に
  マッピングして取り込む**のが正しい設計。これはLLMにやらせる（§4）。

## 4. 審査で落とさないための必須導線 ★最優先で実装

> 審査は、運営が用意するサンプル日記を読み込ませたときの出力で行います。

**サンプルを投入できないアプリは、それだけで評価不能。** 以下を最初に作ってください。

1. 「サンプル日記を読み込む」ボタン、または**テキスト貼り付け→取り込み**の欄を画面に置く。
2. 貼り付けられた7日分のプレーンテキストを、**LLMに一度パースさせて**日付ごとの構造化データに変換し、
   自アプリのデータ形式（タグ・エネルギー・問いへの回答）に流し込む。
   正規表現パースは表記ゆれで壊れるので非推奨。**LLMにマッピングさせるほうが要件にも合致**します。
3. 取り込み後、そのまま「日次まとめ」「週次の振り返り」の両方が動くこと。
4. APIキー入力欄（`type="password"`、`localStorage` 保存）。審査員が自分のキーで動かせる状態に。

動画の尺は2〜3分。**この取り込みが一発で決まるかどうかで動画の印象が決まります。**

## 5. 技術設計（単一HTML）

```
index.html   ← これ1枚。CSS/JSは <style> / <script> にインライン
```

- 状態：`localStorage` に `entries: { "2026-06-02": {...} }` を保存。
- API呼び出しは `fetch` で直接。**JSONモード／スキーマ指定**を使い、パース失敗を防ぐ。
- **失敗時のフォールバック必須**（キー未入力・通信エラー・JSON不正）。動画収録中に落ちると致命傷。

### LLMに渡す入力JSON（基準①がそのまま見る部分）

```json
{
  "today": {
    "date": "2026-06-04", "weekday": "水",
    "mood_tags": ["疲れた", "達成感"], "energy": 3,
    "highlight": "疲れてたけど無理やりジムへ。頭の中の霧が晴れた",
    "small_win": "1時間動けた",
    "answer_to_generated_question": "..."
  },
  "recent": [
    { "date": "2026-06-03", "weekday": "火", "mood_tags": ["落ち込み"], "energy": 2,
      "summary_line": "資料のやり直しを指示され、成長しているのか分からなくなった" }
  ],
  "review_lenses": ["感情が動いた瞬間", "本人が書いていない結びつき", "前日からの変化"]
}
```

`date` / `weekday` / `review_lenses`（振り返りの観点）を明示的に載せているのがポイント。
基準①の文言「日付・その日の入力・振り返りの観点など、良いまとめに必要な情報をセットで」に
一対一で対応しています。**この対応関係をメモ（提出物④）に書くこと。**

過去分は全文でなく**1行サマリー＋数値**（ローリングサマリー）。
トークンを抑えつつ「変化」を語れる情報だけ渡す、という設計判断そのものが評価対象です。

### 受け取る出力スキーマ（日次）

```json
{
  "mirror": "あなたは『頭の中の霧が少し晴れた』と書いた。",
  "gained": ["疲れた状態から動き出せたこと"],
  "pattern": "昨日は『ただ回してるだけ』と書いていた。今日は自分から動いた記録になっている。",
  "tomorrow_action": "明日の予定に、5分でいいので体を動かす枠を1つ置く",
  "mood_score": 3,
  "needs_support": false
}
```

フィールドごとに見せ方を変える（引用は大きく、行動は1枚のカードに）だけで、
「ただの要約表示」との差が一目でつきます。

## 6. プロンプト設計の骨子（提出物③としてそのまま出す）

### 日次まとめ用

```
あなたは、夜の振り返りに寄り添う「記録の相棒」です。
相手は仕事に追われて疲れきった36歳の会社員。これから眠るところです。

【入力】今日の記録と直近数日の記録（JSON）
{data}

【必ず守ること】
1. 出力の冒頭は、ユーザーが今日実際に書いた語句を一箇所そのまま引用することから始める。
2. ユーザーが書いていない出来事・感情を創作しない。書かれた範囲を超えて推測しない。
3. 一般的な助言（「休息も大切です」等）、定型の労い（「お疲れ様でした」等）を書かない。
4. 直近の記録と比べた変化を1点だけ挙げる。読み取れなければ pattern を空文字にする。
5. 明日の行動は「5分以内で終わること」を1つだけ、具体的な動詞で書く。
6. 全体200文字以内。深夜に読むので短く、断定せず、採点や評価をしない。

【安全のための制約】
7. 心理診断・性格のラベリング・決めつけをしない。医療やメンタルヘルスの助言をしない。
   あなたの役割は本人の言葉を映して整理することであり、解釈を押しつけることではない。
8. 自傷・強い希死念慮など緊急性の高い内容が含まれる場合のみ needs_support を true にし、
   まとめは無理に生成せず、本人の言葉を静かに受け止める短い一文だけを返す。

【出力】次のJSONのみを返す。前後に説明文をつけない。
{ "mirror": string, "gained": string[], "pattern": string,
  "tomorrow_action": string, "mood_score": 1-5, "needs_support": boolean }
```

### 週次の振り返り用（基準③の本体）

```
以下は同一人物の複数日の記録です。
{entries}

日ごとの感想ではなく、【日をまたいで初めて見えること】だけを書いてください。

観点：
- 繰り返し現れている語や状況（何日に出たか、回数を数えて示す）
- 感情が動いた瞬間に共通していること（何が起きたときに気持ちが上がったか）
- 本人が書いてはいるが、まだ結びつけていない事柄どうしのつながり
- エネルギーの推移と、それに連動している出来事

禁止：
- 一般論・励まし・アドバイスの羅列
- 本人がすでに自分で書いている気づきを、そのまま言い換えて返すこと
- 1日だけを見ても言えること

各項目に、必ず日付と本人の言葉の引用を根拠として添えること。
性格の診断やラベリングはしないこと。

出力JSON:
{ "recurring": [{"theme": string, "count": number, "evidence": string[]}],
  "energy_trend": string,
  "unconnected_dots": {"observation": string, "evidence": string[]},
  "one_change": string }
```

**効く順に3つ：**
1. **引用を根拠として添えさせる** — 一般論を潰す最強の一手。
2. **「本人がすでに書いている気づきの言い換え」を明示的に禁止** — §3 の「差がつかない出力」を封じ、
   AIを「まだ結びついていない点」探しに追い込む。
3. **「1日だけを見ても言えることは禁止」** — 複数日を渡した意味を出力に強制する。

### サンプル取り込み用（パース＆マッピング）

```
以下は、ある人物が複数日にわたって書いた日記です。原文を一切変更・要約せずに、
日付ごとに分割し、各日を次の構造に変換してください。

- date: 原文の日付表記（例「6/2（月）」）を ISO 形式 YYYY-MM-DD に。年は {year} を補う。
- weekday: 原文の曜日
- raw: その日の原文全文（変更禁止）
- mood_tags: 次から該当するものだけ選ぶ（推測で足さない）: 疲れた/充実/モヤモヤ/焦り/淡々/達成感/落ち込み
- energy: 本人の記述から読み取れる活力を1〜5で。読み取れなければ3。
- highlight: 本人の言葉を使って、その日いちばん頭に残っている事柄を1文で
- small_win: 本人が前に進めたと読める事柄。無ければ空文字

原文に無い出来事を足さないこと。出力はJSON配列のみ。
```

## 7. 「寝る前5分」の体験設計（基準④）

- **ダークテーマを既定**に。深夜の画面まぶしさ対策であることを動画で言及する。
- 文字は大きく、タップ領域は広く。片手・寝転がった姿勢を想定。
- 起動 → 3秒で入力開始。ログインも設定画面も挟まない。
- 「あと2問」などの残量表示。**スキップボタンを各問に置く。**
- 生成待ちに「今日の記録を読み返しています」等の演出（無言のスピナーにしない）。
- 最後は「おやすみなさい」で閉じる。次の行動を要求して終わらない。
- 連続記録日数の表示（筋トレ習慣の人物設定と相性が良い）。ただし途切れを責めない文言にする。

## 8. 提出物（4点・1フォルダにまとめてURL提出）

Googleドライブ等にアップし、URLを提出。
**閲覧・DL権限が制限されていると審査対象外**になるので、共有設定を必ず確認すること。

| # | 提出物 | 注意 |
| --- | --- | --- |
| ① | ソースコード（単一HTML） | **APIキーは削除またはプレースホルダ** |
| ② | 動作動画（2〜3分） | **サンプル日記を読み込ませ、入力→まとめ出力までの一連**を収録 |
| ③ | 設計・実装に用いた主要プロンプト全文 | まとめ生成プロンプト＋**AIに渡す情報の設計**を含む／テキスト |
| ④ | 制作判断のメモ（300字以上） | 何を記録するアプリか／まとめプロンプトの狙い／UXで意識した点／**このアプリならではの工夫** |

③④があるということは、**プロンプトと設計意図が直接読まれる**ということです。
コード内のプロンプトを後から抜き出せるよう、1箇所にまとめて書いておくと提出が楽になります。

④のメモは、基準①〜⑤に一対一で答える構成にすると強い：
「渡している情報（①）／一般論を潰した制約（②）／複数日から何を出すか（③）／寝る前のUX（④）／独自性は◯◯（⑤）」。

## 9. タイムライン（目安4〜4.5時間）

| 時間 | やること |
| --- | --- |
| 0:00–0:30 | コンセプトと問いの設計。**渡すJSON・受け取るJSONのスキーマを先に確定させる** |
| 0:30–1:00 | 単一HTMLの骨組み＋APIキー入力欄＋API疎通（ここで一度動くものにする） |
| 1:00–1:45 | **サンプル日記の取り込み導線**（最優先。未実装だと審査されない） |
| 1:45–2:45 | 日次まとめ・週次振り返りの実装、出力UIの作り込み |
| 2:45–3:15 | 安全設計（needs_support フラグ＋相談窓口カード＋常設リンク） |
| 3:15–3:50 | サンプルを実際に流してプロンプト調整。**一般論が出たら制約を足す**を繰り返す |
| 3:50–4:10 | エラー処理、ダークテーマ整え、APIキーをプレースホルダに差し替え |
| 4:10–4:40 | 動画収録＋提出物③④の執筆 |

## 10. 動作動画（2〜3分）で必ず映すもの

1. サンプル日記の貼り付け → 構造化されて7日分が入る様子
2. 1日分の入力（30秒で終わることを実演）＋**AIが生成した「今日だけの問い」**
3. 日次まとめの出力（**引用から始まっている**ことを指し示す）
4. 週次の振り返り（複数日の傾向が**根拠つき**で出ていること）
5. 口頭で一言ずつ：
   - 「一般論を出さないために、引用を必須にする制約を入れています」
   - 「このアプリの独自性は、問いそのものがAIで前日から生成される点です」

設計意図を口頭で言うだけで、基準①と⑤の評価は目に見えて上がります。

## 11. 提出前チェックリスト

**必須要件**
- [ ] 単一HTMLで完結（外部ファイル依存なし、ブラウザで開けば動く）
- [ ] 実行時にLLM APIを呼んでいる（事前生成・ハードコードでない）
- [ ] **提出コードのAPIキーが削除またはプレースホルダになっている**
- [ ] 安全設計：診断・助言をしないプロンプト制約＋深刻時の相談窓口導線＋常設リンク
- [ ] サンプル日記を貼り付け／ボタンで取り込める
- [ ] 取り込んだサンプルで日次・週次の両方が動く

**品質**
- [ ] 出力が一般論になっていない（引用・固有の語が入っている）
- [ ] 週次が「本人がすでに書いている気づき」の言い換えになっていない
- [ ] 複数日の傾向が日付・引用の根拠つきで出ている
- [ ] 白紙のテキストエリアが最初に出てこない／各問スキップ可
- [ ] ダークテーマ・大きなタップ領域
- [ ] APIエラー・JSON不正時に画面が壊れない

**提出**
- [ ] ①〜④を1フォルダにまとめた
- [ ] **共有リンクの閲覧・DL権限を確認した**（制限されていると審査対象外）
- [ ] 動画にサンプル投入→まとめ出力の一連が収まっている（2〜3分）
- [ ] メモ300字以上、基準①〜⑤に対応している
