# 企画書 #1 『GHOST CROWD』（ゴーストクラウド）

**仮邦題：わたしがいっぱい**
バズスコア **51 / 70** ｜ ベット経路：**配信クリップ爆発（Meccha Chameleon 型）**

---

## 1. ログライン

> **自分の過去のプレイ録画が、群衆になって襲ってくる。その中に紛れて生き残れ。**

---

## 3. なぜ今これか（市場根拠）

- Meccha Chameleon（$4.79・2人・2ヶ月開発）が **2,000万本・ピーク同接34万** を達成。「安い非対称かくれんぼ」に世界的な需要があることが実証された。
- しかし同作のフォロワーは全て **「背景に化ける」の模倣**に留まっており、**「群衆に化ける」という別解が空いている**。
- 群衆に紛れるゲーム（Hitman / Deceive Inc.）は存在するが、いずれも $30〜60 のフルプライスであり、**$5のパーティゲームとしては未開拓**。
- Twitchでは非ゲーム配信が視聴時間の32%。**喋りを止めずに遊べる**（＝棒立ちが正解になる）本作は、Just Chatting との親和性が極めて高い。

## 4. コアループ

```
ラウンド開始
  ↓
[ゴースト側] 群衆の中に紛れて90秒生き残る
[ハンター側] 「生きている人間」を見つけて撃つ
  ↓
ラウンド終了 → 全員の動きが記録され、NPCゴーストとして次ラウンドの群衆に加わる
  ↓
群衆が増える → 隠れやすくなる、が「自分の癖」も増えて特定されやすくなる
  ↓
5ラウンド後、生存ポイント最多のプレイヤーが勝利
```

**この設計の核**：群衆はAIで作らない。**プレイヤー自身の入力ログのリプレイ**である。
だから群衆は毎回違い、癖があり、たまに壁に向かって走り続ける変な奴が混ざる。制作コストはほぼゼロ、面白さは人間由来。

## 5. 詳細ルール

### 5-1. 見た目
- 全キャラクターが **同一の白い無個性マネキン**。名前表示なし、色差なし、身長差なし。
- 区別できるのは **動き方だけ**。

### 5-2. ゴースト側の武器
| アクション | 効果 |
|---|---|
| **フリーズ**（長押し） | 完全静止。だがスタミナを消費し、切れると勝手にフラつく |
| **トレース** | 近くのNPCゴースト1体の動きを3秒だけ完コピする |
| **癖リセット**（1マッチ1回） | 自分の記録済みログを1本削除できる＝「バレた癖」を消せる |

### 5-3. ハンター側の武器
| アクション | 効果 |
|---|---|
| **スキャン**（3秒チャージ） | 半径5m内の「入力遅延の揺らぎ」を可視化。人間は微細に揺れる |
| **射撃** | 2発まで。NPCを撃つと5秒スタン（＝誤射のペナルティ） |
| **ざわめき** | 群衆全体を驚かせる。人間だけが反射的に一瞬動く（ことがある） |

### 5-4. 敗北しても抜けられない
撃たれたプレイヤーは即座に **NPCゴーストの視点**に切り替わり、群衆の中から観戦する。
→ 退出率が下がる。観戦者が「あそこにいるぞ」と叫ぶのが配信の見どころになる。

## 6. バズ設計

### 6-1. 7原則マッピング

| 原則 | 点 | 実装 |
|---|---|---|
| ①5秒ルール | **10** | 「白い人形が大量に棒立ちしている」画は無音1フレームで伝わる |
| ②失敗こそコンテンツ | **9** | スタミナ切れでフラついた瞬間に撃たれる＝完璧な失敗の画 |
| ③人間が乱数 | **9** | 群衆の中身が全部プレイヤーの癖。AIでは絶対に出ない挙動が量産される |
| ④摩擦ゼロ | **9** | $4.99 / 1.2GB / ロビーはリンク1つ |
| ⑤日常寄生 | **3** | 弱い。起動が必要（→ 週末にDiscordで集まる文化に依存） |
| ⑥所有と略奪 | **4** | 弱い。「癖」を資産化するメタはあるが薄い |
| ⑦ミーム代謝 | **7** | ステージとポーズを週次追加。ミームポーズの実装は72時間で可能 |

### 6-2. 想定クリップ（具体的に3本）

1. **「自分の分身に自分がバレる」**
   ハンターが群衆を見て「こいつ絶対○○さん、この歩き方する」と言い当てる瞬間。
   → 視聴者が **「わかる」** と反応する。人格がゲームメカニクスになっている。

2. **「スタミナ切れ全滅」**
   終了3秒前、5人が同時にフリーズ限界を迎えて一斉にフラつき、ハンターに全員狩られる。
   → 無音で完全に成立する笑いの画。

3. **「バグみたいなNPC」**
   前ラウンドで壁にぶつかり続けたプレイヤーの記録が、そのままNPCとして延々と壁に突撃している。
   → 「こいつ誰だよ」でコメント欄が埋まる。**プレイヤー自身がネタを生産している**。

### 6-3. クリップ量産の仕掛け（プロダクト側）
- **オートハイライト**：撃たれた瞬間の前後6秒を自動で mp4 / 縦型 mp4 に書き出し、デスクトップに保存。
- **群衆視点リプレイ**：マッチ後に「NPCとして映っていた自分」を視聴できる。
- **配信者モード**：視聴者には「誰が人間か」を隠す／あるいは全公開する、どちらも選べる（情報格差＝実況の燃料）。

## 8. 開発計画

| フェーズ | 期間 | 内容 | ゲート |
|---|---|---|---|
| P0 縦切り | 2週間 | 白人形／記録リプレイ／撃つ だけ | **社内10人テストで C値（声が出た回数）6回/時を超えるか** |
| P1 コア確定 | 6週間 | 5アクション実装、90秒×5ラウンド、3ステージ | 外部20人テストで S値0.8（無音クリップ理解率） |
| P2 量産 | 8週間 | 10ステージ、マッチメイキング、オートハイライト | 同時100人の負荷試験 |
| P3 CBT | 3週間 | クローズドβ（配信者50名招待） | 配信者のクリップが自然発生するか |
| P4 発売 | — | Steam リリース | — |

**体制**：ゲームプログラマ1／ネットワーク＆サーバ1／アート＆UX1（＋業務委託でSE）

**技術的な軽さ**：群衆は入力ログの再生なので、サーバは**座標同期ではなく短いログの配布**で済む。同時接続あたりのサーバコストが極端に低く、バズ時に落ちない。**TBHがBOTとサーバ負荷で事故った轍を踏まない。**

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **Meccha Chameleon の亜種と見なされる** | 大 | 「群衆＝自分の録画」を **1枚絵とタイトル画面で最初に伝える**。トレーラー冒頭3秒でNPCが変な動きをする画を置く |
| プレイヤー数が少ないと群衆が作れない | 大 | 初回のみ **開発チームが録ったログを種として配布**。2ラウンド目以降はプレイヤー由来に置換 |
| 90秒棒立ちが退屈 | 中 | スタミナ制限で「静止し続けられない」ようにし、常に微細な判断を強制 |
| チート（人間検出ツール） | 中 | 入力揺らぎをサーバ側で平滑化して配信。クライアントに「人間フラグ」を一切送らない |
| バズ後14日で失速 | 大 | **発売前に週次更新3ヶ月分を作り終えておく**。ピーク時に増員しない |

## 11. ローンチ戦略

**T-60日**：Steamページ公開。1枚絵GIF（白人形の群衆）のみでX/TikTokに投下。説明文を書かない。
**T-30日**：マイクロ配信者 **200名**（同接100〜2,000層）に無償キー配布。大手には配らない。理由：小規模配信者は「新作を掘る」動機が強く、かつ同時多発すると **アルゴリズムが"流行"と誤認する**。
**T-14日**：CBT。参加者のオートハイライトがそのままSNSに流れる導線を用意。
**T-0**：発売。**価格を$4.99から動かさない**（セール前提の割引待ちを発生させない）。
**T+3日**：この時点のクリップ上位10本を分析し、**最もバズった要素を強化するパッチを T+7日に出す**。
**T+14日**：初回大型アップデート（新ステージ＋ミームポーズ）で再点火。
