## バズの7原則

| # | 原則 | 一行定義 |
|---|---|---|
| 1 | **5秒ルール** | 音声なし・前情報なし・5秒で「何が起きているか」が伝わるか |
| 2 | **失敗こそがコンテンツ** | 上手いプレイより、事故と全滅の方が面白く撮れるか |
| 3 | **乱数を人間に置く** | 予測不能性の供給源が、システムではなく人間関係になっているか |
| 4 | **摩擦ゼロの入口** | 無料〜$5 / 2GB以下 / 起動60秒 / 招待はリンク1つ |
| 5 | **日常への寄生** | 時間を奪うのではなく、既にある生活時間に居座れるか |
| 6 | **所有と略奪** | 数字が伸びる快感と、それを他人から奪える構造の同居 |
| 7 | **ミーム代謝速度** | 流行を72時間以内にゲーム内へ取り込み、バズを再点火できるか |

### バズの方程式

```
バズ総量 ≒ ( C × S ) × ( E × I ) × M^t

C: 切り抜きたくなる瞬間の発生率（目標 6回/時）
S: 1クリップが無音・無文脈で伝わる率（目標 0.8）
E: クリップを見た人が起動するまでの障壁の低さ
I: 新規1人が引き込む人数（目標 1.5）
M: 更新でバズを再点火する係数 / t: 運営継続月数
```

詳細は [00-research-viral-games-2026.md](./00-research-viral-games-2026.md) を参照。

## 推奨する着手順序

5本は「同じ狙いの5本」ではなく、**異なるバズ経路への分散投資**として設計している。全部同時には作らない。

1. **#3 MY FAKE MUSEUM を最初に出荷する**
   初期投資900万円・開発4ヶ月・損益分岐DAU 8,000。**「バズの7原則」が自社で再現できるかを最小コストで検証する**ための1本。当たれば月商$3M級の上限がある。

2. **並行して #1 GHOST CROWD の縦切りを2週間で作る**
   C値（切り抜きたい瞬間の発生率）とS値（無音理解率）を実測し、4回/時を下回ったらその時点で中止する。

3. **#3 か #1 が当たったら、その現金とコミュニティで #2 / #4 へ**

4. **#5 は当たりが1本出てからのみ着手する**
   UAに現金が要るため、単独では走らせない。ヒット後の「収益の柱」候補。

## 各企画が織り込んでいる「失敗の前例」

本ポートフォリオは、2026年に実際に起きた事故を設計段階で回避している。

| 実際に起きたこと | どの企画で、どう回避しているか |
|---|---|
| TBH に RMT目的のBOTが大量流入し、過剰なアンチチートで**無実のプレイヤーが誤BAN** | **#2**：資産をトレード不可にして「売る対象」を消し、資源に日次ハードキャップをかける。**BAN機能そのものを実装しない**（異常値は丸めるだけ） |
| Grow a Garden が主要開発者の離脱と不評アップデートで2026年1〜3月に失速 | **#3**：週次イベントをテンプレ化し、3ヶ月分を公開前に作り終えてから出す |
| バズ系はピーク後30日でDAU 80〜90%減 | **#1 / #3**：発売前に週次更新3ヶ月分を用意。**ピーク時に増員せず固定費を上げない** |
| Smash Fest! が Google Play から削除 | **#5**：実在建築を使わない／人・生物を出さない／災害連想モチーフを避け、審査ガイドラインの事前レビューを必須化 |
| 常駐アプリへの「キーロガーでは」という疑念 | **#2**：取得項目を回数のみに限定し、**クライアントの通信部分をオープンソース化**。第三者監査レポートを公開 |
| AI生成物の炎上・推論コストの変動費リスク | **#4**：Steam のAI利用開示を初日から明記。原価率を売上の8%に設計し、**推論単価が3倍になっても黒字**の構造にする |
